# ogentic-audit golden vectors — v0.2 (signed mode)

Conformance vectors for format `0x0002` ([`docs/spec/v0.2.md`](../../../docs/spec/v0.2.md) §16), generated by [`tools/gen_vectors_v02.py`](../../../tools/gen_vectors_v02.py) (also reachable as `tools/gen_vectors.py --v02`).

The generator is a second implementation of the format: Ed25519 comes from Python `cryptography` (OpenSSL), CBOR, SSHSIG and the release builder are written out in the script, and spec §3.5 rules 1–3, which OpenSSL does not apply, are checked with a pure-Python curve implementation. Its `--verify` mode is an independent verifier used as a test oracle for every run below.

## Keys

The RFC 8032 §7.1 test keys, so any Ed25519 implementation can confirm them without this repository: **K1** = TEST 1, **K2** = TEST 2, **K3** = TEST 3, **K4** = TEST 1024. Each vector's `inputs.json` repeats their seeds, public keys and grouped fingerprints.

## Layout

Each directory holds:

| File | Purpose |
|------|---------|
| `inputs.json` | `description`, `keys`, and `runs`: the commands to run and their expected results. Writer vectors also carry `writer` (key, `log_id`, session, segment size, records) |
| `log/`, `release/` | The artefact under test, as a third party would receive it (post-tamper where the vector tampers) |
| `chain.json` | For writer and tamper vectors: `log_id`, key, per-segment `chain_start` and final hash, per-record `record_hash`, `body_hash`, `prev_hash`, `signature`, before any tampering (`post_tamper` says whether `log/` was changed afterwards) |
| `allowed_signers`, `cp.json`, `keys/`, `rev/`, … | Trust files, checkpoints, statements and revocations the runs pass in |

A run names `command` (`verify`, `verify-release`, `checkpoint-compare`, `ed25519`), its inputs (`key_fingerprint`, `public_key`, `trust`, `statements` with `statements_source` `operator` or `bundle`, `revocations`, `checkpoints`, `witnesses`, `expect_log_id`, `segment`, `expect_release_id`, `allow_unattested`, HMAC `hmac_key_source` and `env`), and `expect`: the exit code (0 verified, 1 violation, 2 I/O, 3 argument error, 4 not verified) and, where they apply, the compact verdict (`Kind@location`), `reason`, `head_anchored`, elided positions, warnings, witnesses, `records_after_head`, and the trust path.

## Determinism

Ed25519 is deterministic (RFC 8032) and vectors fix `log_id`, the session id and every body nonce, so every byte is reproducible. Body nonces are `SHA-256("ogentic-audit/v0.2/test-nonce" ‖ 0x00 ‖ log_id ‖ u64be(i))`, where `i` counts every record the writer writes, structural records included. A real writer draws nonces and `log_id` from the OS CSPRNG.

Rollover follows the writer's rule: before appending to a segment that already has records, roll over if `bytes_written + framed(record) + framed(segment.finalized) > segment_size_bytes`, where both sizes are computed with `record_id = 2^64 − 1` and the finalize body counted as 160 bytes.

## Consumers

- `crates/ogentic-audit-core/tests/signed_vectors.rs`: rebuilds every writer vector byte for byte with `SignedWriter`, checks `chain.json`, runs every run through the library, checks the Ed25519 edge cases, Appendix A fingerprints, checkpoint comparison, and that `AttestationBuilder` reproduces `release-clean` byte for byte.
- `crates/ogentic-audit-cli/tests/cli_signed_vectors.rs`: runs every command-line run through the binary and checks exit codes, verdicts and reasons.
- `python/tests/test_signed_vectors.py`: the same runs through the Python package.
- `tools/gen_vectors_v02.py --verify`: the independent oracle.

`ed25519-edge/cases.json` is the published test suite of "Taming the many EdDSAs" (Chalkias, Garillot, Nikolaenko, 2020), from github.com/novifinancial/ed25519-speccheck (Apache-2.0); `expected.json` is each case judged under spec §3.5.

Cases git cannot carry (NFD names, symlinks, names that differ only in case) are generated at test time in `crates/ogentic-audit-core/tests/signed_mode.rs`.

## Regenerating

```sh
pip install cryptography
python3 tools/gen_vectors.py --v02            # rewrite every v0.2 vector
python3 tools/gen_vectors.py --v02 --check    # fail if committed bytes drifted
python3 tools/gen_vectors.py --v02 --verify   # run the oracle over every run
```
